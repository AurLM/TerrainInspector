TERRAIN INSPECTOR - WINDOWS VERSION, BUILT BY GITHUB

In your GitHub repository (the one that built the previous .exe), replace everything with the files of this zip,
keeping the folders:
  .github/workflows/build-windows-exe.yml
  app/Program.cs
  app/TerrainInspector.csproj
  app/app.manifest
  terrain-inspector.html      <- the tool, replace it with each new version
  VERSION.txt                 <- just the version number, e.g. 2.5
  README.txt                  <- goes into the folder users get

Push (or on github.com: Add file > Upload files > Commit changes). About 3 minutes later:
Actions tab > latest "Build Windows exe" run > Artifacts > "Terrain Inspector 2.5".
Upload that zip to Nexus AS IT IS. Don't unzip and re-pack it, don't add other files, and use ZIP (not RAR).

What changed from the previous .exe, and why:
- The tool page is no longer packed INSIDE the .exe. It is page\terrain-inspector.html next to it.
  An .exe that carries another file inside it and hands it out at run time looks like a self-extracting
  file, which Nexus sends to manual review. Now the .exe is small and only opens a window.
- Nexus's scanner can now preview every file in the zip (it can't look inside an .exe).
- Full version details (name, author, version, description) in the .exe's properties.
- Declares that it never needs admin rights and supports Windows 10/11.
- No internet code: if WebView2 is missing, it just says so (no download link opened from the program).
- The build checks there is one small .exe, no archive inside the folder, and every needed file.
